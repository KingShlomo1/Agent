# FamilyTripAI

An AI family-travel planning assistant. A user describes a trip and the agent
builds a complete plan — destination imagery, flights & hotels with booking
links, weather, activities, family-friendly restaurants, travel tips, currency,
and a day-by-day itinerary — by calling an LLM (Groq) with a set of travel tools.

## Architecture

**`worker.js` is the single source of truth.** It is a self-contained
Cloudflare Worker that:

- serves the entire single-page app (HTML/CSS/JS are embedded inline), and
- handles `POST /chat` (the streaming agent) and `POST /search` (structured
  data for the Trips / Prices / For Me browsing tabs)

by calling the Groq API directly with the travel tools defined at the top of the
file.

There is intentionally no separate backend or build step — everything lives in
`worker.js`. (A previous duplicate Python/FastAPI implementation and a separate
`static/index.html` were removed to eliminate drift.)

## Deploy

```bash
npm i -g wrangler        # if not already installed
wrangler deploy          # uses wrangler.toml (main = worker.js)
```

## Configuration

- **Groq API key** — currently supplied by the client (stored in `localStorage`)
  and sent with each request. Get a free key at https://console.groq.com.
- Model selection is centralised in the `CHAT_MODEL` / `SEARCH_MODEL` constants
  at the top of `worker.js`.

## External services used

- Groq (LLM) — chat + structured search
- Open-Meteo + Nominatim (OpenStreetMap) — weather & geocoding
- open.er-api.com / Frankfurter — currency rates
- DuckDuckGo Instant Answer — web search
- Pollinations — destination image generation
- Booking.com / Hotels.com / Airbnb / Google Flights / Skyscanner / Kayak /
  Viator — outbound booking links

## Notes

- Flight/hotel/activity cards in the browsing tabs are **illustrative planning
  estimates generated by the LLM**, not live inventory. Use the booking links
  for real prices.
- Model and external API responses are untrusted; all rendered HTML passes
  through DOMPurify (`sanitizeHtml` / `mdParse` in the client) before insertion.
